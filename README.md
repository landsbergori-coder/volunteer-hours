# מחויבות אישית — מערכת לניהול שעות התנדבות

אפליקציית ווב מלאה בעברית (RTL) לניהול ורישום שעות התנדבות של תלמידי שכבות **י'** ו-**י"א**.
המערכת תומכת בארבעה סוגי משתמשים — תלמיד, מחנך/ת, מנהל מערכת, ואחראי מקום התנדבות — לכל אחד
דשבורד והרשאות נפרדות.

---

## טכנולוגיות

| שכבה | טכנולוגיה |
|------|-----------|
| Framework | Next.js 15 (App Router) + TypeScript + React 19 |
| בסיס נתונים | PostgreSQL (Neon) + Prisma ORM |
| עיצוב | Tailwind CSS + RTL מלא + פונט עברי (Heebo) |
| אימות | JWT ב-httpOnly cookie (`jose`) + סיסמאות מוצפנות (`bcryptjs`) |
| הרשאות | Middleware לפי נתיב + בדיקת role בכל Server Action |
| ולידציה | Zod (משותף לקליינט ולשרת) |
| ייצוא | SheetJS (`xlsx`) — CSV ו-Excel |

---

## התקנה והרצה (מקומית)

דרישה מוקדמת: **Node.js 18+** (נבדק על Node 24) ובסיס נתונים **PostgreSQL** (מומלץ Neon, חינם).

```bash
# 1. התקנת תלויות (כולל יצירת Prisma Client)
npm install

# 2. הגדרת משתני סביבה: העתק את .env.example ל-.env ומלא את מחרוזות החיבור מ-Neon
#    (DATABASE_URL = pooled, DIRECT_URL = direct) ואת JWT_SECRET

# 3. יצירת הסכמה בבסיס הנתונים
npx prisma migrate dev

# 4. טעינת נתוני דוגמה
npm run db:seed

# 5. הרצת השרת המקומי
npm run dev
```

האפליקציה תהיה זמינה בכתובת: **http://localhost:3000**

> איפוס מלא של בסיס הנתונים (מוחק הכל וטוען מחדש את נתוני הדוגמה): `npm run db:reset`

## תפקידים והרשאות

- **תלמיד** — נרשם עצמאית; מזין מקום התנדבות, מדווח שעות (חישוב אוטומטי), כותב רפלקציות (אחת לכל מחצית), רואה את ההיסטוריה שלו בלבד.
- **מחנך/ת** — רואה **רק** את תלמידי כיתתו; טבלה עם סינון ומיון (שם / שעות / מקום / חסרי רפלקציה / מעט שעות יחסית לכיתה) וכרטיס תלמיד מלא.
- **מנהל מערכת** — רואה את **כל** התלמידים, סטטיסטיקות (ממוצעים לכיתה, התפלגות מקומות, חסרי שעות/רפלקציה), סינון מתקדם, ייצוא CSV/Excel, ויצירת חשבונות מחנכים ואחראים.
- **אחראי מקום התנדבות** — רואה **רק** תלמידים עם מקום פעיל במקום שבאחריותו; מזין הערכה מילולית (התלמיד אינו יכול לערוך אותה).

**שיוך אחראי**: אחראי מקבל חשבון מהמנהל. כאשר תלמיד מזין בפרטי מקום ההתנדבות אימייל התואם
לחשבון אחראי קיים — השיוך נוצר אוטומטית והתלמיד מופיע אצל האחראי.

## כללי לוגיקה עסקית

- **חישוב שעות** — אוטומטי משעת התחלה וסיום, בפורמט עשרוני (לדוגמה 2.5). נדחה דיווח שבו שעת הסיום ≤ שעת ההתחלה, או תאריך/שעה לא תקינים.
- **דיווח שעות** חסום ללא מקום התנדבות פעיל.
- **שינוי מקום התנדבות** — סוגר את המקום הקודם (`is_active=false`, `end_date`) ושומר אותו בהיסטוריה. **כל השעות הקודמות נשמרות** ומשויכות למקום שבו בוצעו; סך השעות מסכם את כל המקומות.
- **רפלקציה** — אחת בלבד לכל מחצית (אילוץ ייחודיות במסד הנתונים).

## פריסה ל-Netlify

האפליקציה מוכנה לפריסה על **Netlify** עם בסיס נתונים **PostgreSQL מאוחסן ב-Neon**.
(SQLite אינו נתמך ב-serverless — לכן המעבר ל-PostgreSQL.)

### א. הקמת בסיס נתונים ב-Neon
1. הרשמה ב-[neon.tech](https://neon.tech) → יצירת Project.
2. מה-Dashboard מעתיקים שתי מחרוזות חיבור:
   - **Pooled** (עם `-pooler` בכתובת) → `DATABASE_URL`.
   - **Direct** (ללא `-pooler`) → `DIRECT_URL`.
3. מזינים אותן ל-`.env` המקומי ומריצים פעם אחת מהמחשב:
   ```bash
   npm run db:deploy   # יוצר את הסכמה ב-Neon
   npm run db:seed     # טוען נתוני דוגמה (אופציונלי בייצור)
   ```

### ב. פריסה ל-Netlify
חיבור דרך Git (מומלץ):
1. `git init && git add . && git commit -m "initial"` → push ל-GitHub.
2. ב-Netlify: **Add new site → Import an existing project** → בחירת הריפו.
3. תוסף `@netlify/plugin-nextjs` ו-`netlify.toml` כבר מוגדרים — אין צורך לשנות את פקודת ה-build.
4. **Site settings → Environment variables**, הזנת:
   - `DATABASE_URL` (pooled), `DIRECT_URL` (direct), `JWT_SECRET` (אותו ערך כמו מקומי).
5. **Deploy** — בכל push חדש Netlify יבנה ויפרוס אוטומטית.

> חלופה ללא Git: `npx netlify-cli deploy --build --prod` (לאחר הגדרת משתני הסביבה ב-Netlify).

## ניהול מנהלי מערכת

מנהל אינו נרשם דרך טופס (מטעמי אבטחה). יצירת המנהל הראשון נעשית פעם אחת מהמחשב:

```bash
node scripts/create-admin.mjs <email> <password> "שם מלא"
```

- אם האימייל קיים — הסיסמה והתפקיד יעודכנו (role=ADMIN).
- המנהל נוצר עם **דרישה להחליף סיסמה בכניסה הראשונה**.

לאחר התחברות, מנהל יכול לנהל מנהלים נוספים במסך **ניהול מנהלים** (`/admin/admins`):
יצירת מנהל חדש (סיסמה זמנית), איפוס סיסמה, ומחיקה. תמיד יישאר לפחות מנהל אחד, ואי אפשר למחוק את עצמך.

**החלפת סיסמה בכניסה ראשונה:** כל חשבון שנוצר ע"י מנהל (מנהל/מחנך/אחראי) מקבל סיסמה זמנית,
ובכניסה הראשונה מופנה אוטומטית ל-`/change-password` ונחסם משאר המערכת עד שיחליף אותה.

## מחיקת נתונים (מנהל בלבד)

- **תלמיד בודד** — כפתור בכרטיס התלמיד; מוחק את התלמיד וכל נתוניו (שעות, רפלקציות, שיוכים, הערכות).
- **מחנך/אחראי** — כפתור במסך **ניהול חשבונות**. תלמידי המחנך **נשמרים** (עוברים למצב ללא מחנך). מחיקת אחראי מוחקת גם את ההערכות שכתב ומנתקת אותו ממקומות ההתנדבות.
- **שכבה שלמה** / **כל הנתונים** — מסך **ניהול נתונים** (`/admin/data`), עם אישור בהקלדה. "כל הנתונים" שומר את חשבונות המנהלים. מומלץ לייצא גיבוי לפני מחיקה.

## ייצוא רפלקציות והערכות אחראי (Excel)

- **מחנך/ת** — מהדשבורד "ייצוא הכיתה", או מכרטיס תלמיד "ייצוא תלמיד". מוגבל לתלמידי כיתתו.
- **מנהל** — מהדשבורד: כל התלמידים / לפי שכבה (י' / י"א), ומכרטיס תלמיד: תלמיד בודד.
- קובץ ה-Excel כולל לכל תלמיד: רפלקציה מחצית א', רפלקציה מחצית ב', והערכות האחראי (עם מקום, כותב ותאריך).

## הערות אבטחה (להרצה אמיתית)

- `JWT_SECRET` כבר נוצר אקראית ב-`.env`; יש להזין את **אותו ערך** במשתני הסביבה של Netlify.
- קובץ `.env` מוחרג מ-git (`.gitignore`) — הסודות אינם עולים לריפו.
- מחרוזות החיבור והסיסמאות מנוהלות כמשתני סביבה ב-Netlify בלבד, לא בקוד.
- מומלץ למחוק את משתמשי הדוגמה (כולל `admin@school.il` עם סיסמת ברירת המחדל) לפני שימוש אמיתי, ולהשתמש במנהל שנוצר דרך הסקריפט.
